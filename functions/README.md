# שרת תשלומי Trendy

Firebase Functions v2, Node 22. האפליקציה משתמשת ב־Firebase ID token. סוד הסוחר וטוקן PayPal נמצאים בשרת בלבד.

השרת בודק בעלות, מחירים מתוך Firestore, כתובת, capture במצב COMPLETED, מטבע, סכום ומזהה סוחר. הפריטים והכתובת נשמרים בצילום קבוע. שמירת הזמנה וניקוי הפריטים שנרכשו הן טרנזקציה אחת. קריאה חוזרת מחזירה את אותה הזמנה. מזהים קבועים מגינים על ניסיונות יצירה וגבייה חוזרים.

## הפעלה ידנית נדרשת

הקוד לא פורסם בענן. עד הפעלת הפונקציות PayPal יחזיר שגיאת שירות, ולא יסומן תשלום כהצלחה.

1. התקן תלויות מקומיות עם Node 22: `npm ci --prefix functions --ignore-scripts`.
2. התחבר דרך ממשק ההתחברות של Firebase ובחר את אותו פרויקט שבו משתמשת האפליקציה.
3. הגדר ב־Secret Manager את PAYPAL_CLIENT_ID ואת PAYPAL_SECRET. אין לשמור ערכים בקוד או בצ׳אט. בטל והחלף את הסוד הישן שהיה באפליקציה; הסרתו מהקוד אינה מבטלת APK ישן.
4. הגדר PAYPAL_MERCHANT_ID למזהה הסוחר, ו־PAYPAL_ENVIRONMENT ל־sandbox. מעבר ל־live הוא פעולה ידנית נפרדת.
5. התאם את חוקי Cloud Firestore הקיימים לפני הפעלה, לפי הסעיף הבא. לא נמצא בפרויקט מקור החוקים שפורסמו.
6. פרסם ידנית את functions codebase בשם payments לאזור us-central1. כתובת השירות באפליקציה נגזרת מ־Firebase.app.options.projectId.
7. בדוק ב־Sandbox רכישה, ביטול, callback חוזר וניסיון אישור חוזר אחרי תקלה. נדרש capture COMPLETED והזמנה אחת בלבד.

## דרישות הרשאות בענן

- pendingCheckout ו־paypalPending: חסימת גישה מהלקוח; גישה רק לשרת Admin SDK.
- הזמנות עם token של PayPal: יצירה ועדכון רק בשרת. קריאה רק לבעל ההזמנה ולמנהל מורשה.
- תשלום במשלוח: בעלות של המשתמש המחובר, token ריק, מזהה חדש ופריטים/סכום/כתובת תקינים. יש לוודא שאין checkout של PayPal עם אותו מזהה. בדיקות לקוח לבדן אינן גבול אבטחה מול אפליקציה ששונתה בזדון.
- מסמך לקוח: גישה רק לבעליו. PrivateData/role ניתן ליצירה עצמית רק עם isAdmin=false. אין לאפשר שדרוג תפקיד עצמי.
- בדוק את החוקים המותאמים בסביבה מבודדת לפני פרסום. לא בוצעה בדיקת הרשאות מול הענן.

יצירת קובץ חוקי Cloud Firestore נחסמה אוטומטית כעריכת קובץ מדיניות מוגן. ההגנות לא שונו כדי לעקוף חסימה זו.

## בדיקות

`npm --prefix functions test` מריץ את כל בדיקות השרת. `npm --prefix functions run check` בודק תחביר.

הבדיקות מריצות את קוד האימות ואת Firestore adapter מעל transaction store מבודד. הן אינן חיבור לענן ואינן אישור לחוקי הפרויקט שפורסמו. אין חיובים אמיתיים.
